# GitHub workflow quick reference

1. Create a branch to keep a proposed change separate from `main`.
2. Commit a small, focused change with a descriptive message.
3. Open a pull request and explain what changed and why.
4. Check the diff and any automated checks before merging.
5. Merge the pull request to bring the change into `main`.

For shared or production repositories, follow the project's review and branch-protection requirements.

The guided exercise is tracked in [issue #1](https://github.com/return-sin/skills-introduction-to-github/issues/1).
